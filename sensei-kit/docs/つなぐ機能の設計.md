# つなぐ機能の設計（案）— 共有・連絡・宿題の配布・学習記録

先生の道具箱は、サーバーを使わない（データはブラウザの中だけ）。
そのため「人と人をつなぐ」機能のうち、次の4つはここだけでは足りない。数学ポータル（math-dialogue の `portal/`、Classi のような入口）に足す案をまとめる。

| 機能 | いま（道具箱） | 足りないこと | どこで |
|---|---|---|---|
| 予定・リマインダーの共有 | リンク・ファイル・.ics で「写して渡す」 | あとで直したら相手にも反映される、ずっと同じものを見る共有 | 学年の Googleカレンダー（すぐ）／ポータル（段階2） |
| 連絡 | 文をつくるところまで（連絡テンプレート・学級通信。コピーして、いまの連絡手段に貼る） | 先生→生徒・保護者に届ける、生徒→先生のやりとり | ポータル（段階1は先生→クラスの一方向だけ） |
| 宿題の配布 | 配る文・QR、提出チェック（先生が記録） | 生徒の端末に届く・生徒が「やった」を送る | ポータル（段階1） |
| 生徒の学習記録 | なし（先生の提出チェックだけ） | 生徒自身の記録 | ポータルにすでにある（わたしの記録・今日のようす） |

## 何が大変か（正直に）

技術としては、ポータルの作り（先生ごとの ID・パスワード、番号だけの名簿、RPC だけで読み書き）に足せば、どれも作れる。大変なのは、技術より次のところ。

1. **だれが、何を見られるか**：先生は担当クラスだけ、生徒は自分のクラスだけ。保護者を入れると、アカウントの配り方・なくしたときの救済・きょうだいの扱いが一気に増える。
2. **個人情報**：いまのポータルは「名前を保存しない（番号だけ）」で、学校が特定される手がかりも増やさない作り。連絡に自由記述を入れると、名前や悩みが書かれる。保存期間・消し方・見られる人を決めて、学校（と教育委員会のきまり）の許可をとる必要がある。
3. **連絡は運用が本体**：夜に届いた連絡にいつ返すか、緊急の連絡はどう受けるか、いじめにつながる書き込みをどう防ぐか。Classi や tetoru などが大きな会社で回しているのはここ。最初から双方向にせず、一方向（先生→クラス）から始める。
4. **止まったときに困る**：配布や連絡を道具に頼ると、止まった日に授業が回らない。紙・口頭の手段を残しておく。

## 段階案

### 段階0（いま）
- 道具箱：名簿・席替え・係決め・当番表・時間割・カレンダー・リマインダー・宿題の提出チェック・学級通信・連絡テンプレートは、各先生のブラウザの中で完結。
- 連絡：連絡テンプレートと学級通信で「文」をつくり、コピー・印刷・Word にして、いまの連絡手段（連絡帳アプリ・メール・紙）で届ける。届けるところは、学校が決めた手段のまま。
- 共有：リンク（`#share=…`）とファイルで写して渡す。学年でずっと同じ予定を見たいときは、学年の Googleカレンダーに .ics を取り込む。
- 宿題：道具箱の「配る文・QR」を、いま使っている連絡手段（Classroom・Teams・連絡帳アプリ）に貼る。

### 段階1：ポータルに「お知らせ」と「宿題」（先生→クラスの一方向＋「やった」ボタン）
生徒が書けるのは「やった」の印だけ（自由記述なし）。名前は持たない。

```sql
-- 案：お知らせ（先生 → クラス）
create table if not exists portal_notices (
  id          bigint generated always as identity primary key,
  school      text not null,
  class       text not null,                 -- 例: 1-2
  teacher_id  text not null references portal_teachers(teacher_id) on delete cascade,
  title       text not null check (char_length(title) <= 80),
  body        text not null default '' check (char_length(body) <= 800),
  publish_on  date not null default ((now() at time zone 'Asia/Tokyo')::date),
  until_on    date,                           -- この日を過ぎたら出さない
  created_at  timestamptz not null default now()
);
-- 案：宿題（配布）と「やった」の印
create table if not exists portal_assignments (
  id          bigint generated always as identity primary key,
  school      text not null,
  class       text not null,
  teacher_id  text not null references portal_teachers(teacher_id) on delete cascade,
  subject     text not null default '',
  title       text not null check (char_length(title) <= 120),
  note        text not null default '' check (char_length(note) <= 400),
  link        text not null default '' check (link = '' or link ~ '^https://'),
  due_on      date,
  created_at  timestamptz not null default now()
);
create table if not exists portal_assignment_marks (
  assignment_id bigint not null references portal_assignments(id) on delete cascade,
  account_id    text not null,                -- quiz_accounts と同じ（学校コード＋出席番号）
  done_at       timestamptz not null default now(),
  primary key (assignment_id, account_id)
);
alter table portal_notices enable row level security;
alter table portal_assignments enable row level security;
alter table portal_assignment_marks enable row level security;
-- ポリシーは作らない（RPC 経由だけ）。いまのポータルと同じ。
```

RPC（いまの `portal_set_lesson` と同じく、毎回 `_portal_auth` と `_portal_can_class` で確かめる）：

| RPC | だれが | すること |
|---|---|---|
| `portal_post_notice(先生, パスワード, クラス, 題, 本文, 出す日, 終わる日)` | 先生 | お知らせを出す |
| `portal_post_assignment(先生, パスワード, クラス, 教科, 題, メモ, URL, 締切)` | 先生 | 宿題を配る |
| `portal_assignment_status(先生, パスワード, 宿題ID)` | 先生 | 「やった」の番号の一覧と、まだの番号（`portal_rosters` と比べる） |
| `portal_student_today(…)` に `notices` と `assignments` を足す | 生徒 | ホームに、お知らせとまだの宿題が並ぶ（15秒ごとの更新はそのまま） |
| `portal_mark_done(アカウント, パスワード, 宿題ID)` | 生徒 | 「やった」を押す（毎回パスワードを確かめる） |

道具箱との橋わたし：
- 同じサイト（同じドメイン）に置けば、道具箱の宿題から「ポータルに配る」ボタンを出せる（`portal/tools/deploy.cjs` に `sensei-kit/` を足す）。
- 名簿は番号どうしで合わせる（ポータルは番号だけ、道具箱は名前があってもよい）。「やった」の番号を、道具箱の提出チェックに「済」として取り込む。名前はサーバーに出ていかない。

目安：SQL・先生画面・生徒画面・確認で、数日〜1週間（いまのポータルの作りをそのまま使えるため）。

### 段階2：先生どうしの共有（学年・学校の予定）
- `portal_events`（学校・学年の予定）を、管理者と学年の先生が書き、同じ学校の先生が読む。
- 道具箱のカレンダーに「ポータルの予定」を、リマインダー・宿題と同じように重ねて出す（読むだけ）。
- ここまでは生徒の情報が入らないので、許可がとりやすい。

### 段階3：連絡（双方向・保護者）
- 先にきめること：返信する時間帯、緊急の連絡の受け方、記録の保存期間、見られる人、書き込みの見守り。
- 学校で使っているサービス（Classi・tetoru・Google Classroom など）で足りるなら、つくらずにつなぐ（配る文・QR・.ics を渡す）ほうが、先生も保護者も迷わない。
- つくるなら、まず「先生→保護者の一方向」＋「読みました」だけ。

## 学習記録について
- 生徒自身の学習記録は、ポータルにすでにある（小テスト・振り返り・学習時間・家庭学習ノート・応用チャレンジを「わたしの記録」に。先生は「今日のようす」）。
- 道具箱から足すなら、段階1の「やった」の印を、わたしの記録に並べるところから。
- 先生のメモ（所見の下書きなど）は、サーバーに出さず道具箱の中だけに置くのがよい。
